# Alternating features (Divi 5)

Purpose, SEO notes and variations: [the shared recipe](../../sections/alternating-features.md). This page is its Divi 5
structure, field mapping and worked example; how to read them is in the [Divi 5 recipes README](../README.md).

## Structure
```text
section (adminLabel "Alternating Features")
├─ row "Feature 1" columnStructure "1_2,1_2" (all breakpoints)
│  ├─ column 1_2: image
│  └─ column 1_2: heading (h3) · text
├─ row "Feature 2 - Desktop" columnStructure "1_2,1_2", disabledOn tablet + phone
│  ├─ column 1_2: heading (h3) · text
│  └─ column 1_2: image
└─ row "Feature 2 - Tablet and phone" columnStructure "1_2,1_2", disabledOn desktop (same copy, image first)
   ├─ column 1_2: image
   └─ column 1_2: heading (h3) · text
```

Every section, row and column carries `module.decoration.layout` → `{"display": "block"}` (a single-column row
states `columnStructure` `"4_4"`); every block `builderVersion` = `site.divi_version`.

## Field mapping
| attribute | token path | fallback if the site has none |
|---|---|---|
| section `module.decoration.background` → `color` | `section_exemplars[adminLabel=Why Choose Us].attrs.module.decoration.background` (`#ffffff`) | a light `colors.palette` hex |
| section `module.decoration.spacing` → `padding` (+`tablet`/`phone`) | the same exemplar's `module.decoration.spacing`, all three breakpoints (90/60/45px) | `spacing.section_padding[2][0]` |
| row `module.decoration.sizing` → `width`, `maxWidth` | no light-section `1_2,1_2` row bundle: `spacing.row.width[0][0]` / `spacing.row.max_width[0][0]` (`90%` / `1200px`) | same |
| `h3` title `title.decoration.font.font` | no light-section `h3` bundle. The sample's `typography.scale.h3` (Lato 400, `#475569`, 18px) is the number counters' title style (a counter title is an `h3`), too weak for a title: take `typography.heading_font` + `"700"` + the `h2` color (`gcid-r6navy0001`) at `"20px"`, `lineHeight` `"1.3em"`, `headingLevel` `"h3"` | same |
| body text `content.decoration.bodyFont.body.font` | `typography.body_font` + `"400"` + the light-section body color `#475569` (the "About" text bundle's color; a `colors.palette` entry whose `roles` include `content.decoration.bodyFont.body.font.color`) + `"16px"`, `lineHeight` `"1.7em"` | same |
| image `image.decoration.border` → `radius` (4 corners, `sync` `"on"`) | `shapes.radii[0][0]` (`gvid-r6radius01`) | square corners: leave it out |
| image `image.innerContent` → `src`, `alt` | the site's Media Library and a real description, never a token | — |
| row `module.decoration.disabledOn` | fixed technique values, not tokens (Responsive rules) | same |

## Responsive rules

- **Why Feature 2 is written twice.** A row's columns render in source order at every width, and two `1_2`
  columns stack below 981px (tablet and phone). Feature 2's desktop order puts the image second, so stacked it
  would show the text first. The recipe keeps two sibling rows with identical copy and shows one per range:
  - "Feature 2 - Desktop": `module.decoration.disabledOn` →
    `{"desktop": {"value": "off"}, "tablet": {"value": "on"}, "phone": {"value": "on"}}`;
  - "Feature 2 - Tablet and phone" (image column first): `{"desktop": {"value": "on"}, "tablet": {"value": "off"},
    "phone": {"value": "off"}}`.
- **State all three breakpoints.** `disabledOn` values don't inherit downward the way design values do: with only
  `desktop` `"on"` and `phone` `"off"`, the row still showed at 800px (live check). Divi's converter writes the
  pseudo-breakpoints `desktopAbove`/`tabletOnly` for Divi 4's `disabled_on`; both forms are valid, the recipe
  writes the plain three.
- Unlike the Divi 4 recipe, tablet gets the stacked copy too, because the columns already stack there.
- Hiding a row is CSS (`display: none`), so the copy is in the page source twice: keep both rows byte-identical.
- The section padding copies all three breakpoints of the bundle it comes from; no `_last_edited` flag, the `tablet`/`phone` keys are the switch.

## Checklist
- [ ] `python3 scripts/validate.py page.html --tokens tokens.json` — 0 errors, no `W5_UNKNOWN_VARIABLE`/`W5_UNKNOWN_PRESET`; this section alone: `python3 scripts/validate.py section.html --tokens tokens.json --fragment` (`tokens.json` is the target site's own; `recipes/divi5/sample-tokens.json` is only the example's fictional brand)
- [ ] `python3 scripts/preview.py render page.html --tokens tokens.json --out preview.html` — show the user and **stop until they approve it** ([README §7](../README.md#7-the-verification-loop))
- [ ] Only after that approval: `python3 scripts/publish.py draft page.html --site "$SITE" --user "$WP_USER" --title "…"` — review its `preview_url` before publishing ([publishing](../../../reference/publishing.md))
- [ ] at 1440px Feature 1 shows the image left and Feature 2 the image right; at 800px and 390px **both** features show the image before their text — no `h1` on this section, the titles are `h3`
- [ ] every image has alt text and a Media Library URL; the two Feature 2 rows carry identical copy
- [ ] contrast: every text color on its background is at least 4.5:1 (3:1 only for text of 24px, or 19px bold, and up), hover and active states included ([README §2](../README.md#contrast)): navy titles on white 14.9:1, `#475569` body on white 7.6:1
