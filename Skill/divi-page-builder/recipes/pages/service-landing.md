# Service landing

**Use for:** the primary money page for one service line (e.g. "Emergency Plumbing") — the page a
PPC or organic search visitor lands on to learn what you do, trust you, and call or book. ·
**SEO:** exactly one `h1`, supplied by the hero; every other section heading is `h2`, with `h3`
used one level down for sub-items inside a section (feature titles, step titles, stat labels) so
the outline never skips a level.

## Structure

| # | Section | Recipe | Tone | Heading it contributes |
|---|---|---|---|---|
| 1 | Hero | [Hero split](../sections/hero-split.md) | dark | `h1` |
| 2 | Trust bar | [Trust bar](../sections/trust-bar.md) | light (gray) | none |
| 3 | Services | [Services grid](../sections/services-grid.md) | light | `h2` + `h3` (blurbs) |
| 4 | Why it matters | [Alternating features](../sections/alternating-features.md) | light | `h3` (feature titles; no section `h2` of its own — it borrows the `h2` already established by Services, so it must never be the first content section after the hero) |
| 5 | By the numbers | [Stats counters](../sections/stats-counters.md) | light (gray) | `h3` (each `et_pb_number_counter`'s `title` defaults to `h3`) |
| 6 | Testimonials | [Testimonials](../sections/testimonials.md) | light | `h2` |
| 7 | FAQ | [FAQ](../sections/faq.md) | light | `h2` + accordion (set `toggle_level="h3"` explicitly — the module's own default is `h5`, which would skip `h3`/`h4`) |
| 8 | CTA band | [CTA band](../sections/cta-band.md) | dark | `h4` (explicit in the recipe; safe here because Services/Alternating Features already pushed the outline to `h3`) |

## Rhythm

Alternate `section_tone` dark → light → light → light → light → light → light → dark, matching
each section's `admin_label` against `section_exemplars` the way the individual recipes do —
Hero and the closing CTA band are the only dark sections, bookending an otherwise light page so
the two calls to action (call now / get a quote) are the visual anchors. The padding scale steps
down slightly for the two dark bookends (Hero/CTA band use the `96px`/`70px` band) versus the
`80px`-`90px` band most light sections use — copy each section's own padding straight from its
recipe rather than inventing a page-level scale.

## H1/H2 placement

- **One `h1`:** the hero's headline. Nothing else on the page may use `title_level="h1"` or
  `header_level="h1"`.
- **`h2`:** one per major section heading (Services, Testimonials, FAQ). Trust Bar and Stats
  Counters intentionally have no section-level heading — a bare row of logos or numbers doesn't
  need one, and skipping it doesn't break the outline because no heading is emitted at all there.
- **`h3`:** sub-items inside a section that already has an `h2` (service blurbs, feature titles,
  stat labels, FAQ accordion items).
- **`h4`:** only the closing CTA band's `et_pb_cta` title, which the recipe already sets to
  `header_level="h4"` — one step below the heading right before it (the FAQ items' `h3`), which is
  what `validate.py` checks (`W_HEADING_SKIP` fires on any jump of two or more levels going deeper).

## Internal links

- Each `et_pb_blurb` in Services links to that service's own page (`url` attribute) — never a
  bare anchor, so the service still has a real destination if JS fails.
- The hero's button and the CTA band's button both point at `tel:` — a phone-first business's
  single conversion action, not a form the visitor has to fill out mid-emergency.
- No navigation is added inside the page body; the site's global header supplies the primary nav.
